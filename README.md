# 备份专网故障定位与换表轮次规划

备份专网出现流量断路或绕行时,值班员要知道该去哪里补测。网页沿用已填的
**拓扑**与**路由表**,按**已换设备勾选项**确定当前用表(勾选=换版后,未勾选
=换版前),并做两件事:

1. **故障定位**:录入同一时段的实测记录(每条:入口、目标 IPv4、结果——出口名 /
   断路 / 环路),再填最多 12 条可补测的入口与目标。网页推演**无故障**及**每条
   链路、每个出口单独失效**的场景,只保留与全部实测相符的场景,把在全部可补测项
   上结果相同的场景归为一组,列出各组、区分所有组所需的**最少补测项**以及各组的
   **预期补测结果**。没有场景符合时,明确提示**观测与假设不符**。
2. **换表轮次规划**:填入保通要求后,网页给出换表轮次最少的整表切换计划,支持
   中途续排与失败状态(断路 / 环路 / 错出口)的逐跳证据。

## 输入格式

**拓扑** `topology.json`:链路为点到点子网;出口为挂在某台路由器上的外部下一跳子网。

```json
{
  "links": [{"a": "R1", "b": "R2", "subnet": "10.0.12.0/30"}],
  "egresses": [{"name": "E1", "router": "R1", "subnet": "198.51.100.0/30"}]
}
```

**路由表** `routes.json`:每台路由器 `before` / `after` 两张整表,逐条 `prefix` + `next_hop`。
`next_hop` 落在链路子网内即转发给链路对端,落在出口子网内即从该出口出网,否则视为断路。

```json
{
  "R1": {
    "before": [{"prefix": "10.1.0.0/16", "next_hop": "198.51.100.2"}],
    "after":  [{"prefix": "10.1.0.0/16", "next_hop": "10.0.12.2"}]
  }
}
```

**实测记录与补测项**(故障定位,`POST /api/diagnose`):

```json
{
  "switched": ["R4", "R5"],
  "measurements": [
    {"ingress": "R1", "target": "10.1.0.5", "result": "blackhole"},
    {"ingress": "R4", "target": "10.1.0.5", "result": "ok", "egress": "E2"}
  ],
  "candidates": [
    {"ingress": "R2", "target": "10.1.0.5"},
    {"ingress": "R3", "target": "10.1.0.5"}
  ]
}
```

`result` 取 `ok` / `blackhole` / `loop`;`ok` 必须给出 `egress`。
`candidates` 最多 12 条,会按“入口 + 目标”去重。

**保通要求** `requirements.json`(换表计划用):

```json
{
  "requirements": [
    {"name": "业务A", "ingress": "R1", "target": "10.1.0.0/16",
     "allowed_egress": ["E1", "E2"]}
  ]
}
```

`examples/` 目录是内置示例(网页可一键载入):旧路径 `R1→R2→R3→E1`,新路径
`R1→R4→R5→E2`,典型“建新路 → 切换 → 拆旧路”流程。计划为最少 3 轮
`{R4,R5} → {R1} → {R2,R3}`:R1 换表前 R2/R3 必须留旧表,R1 换表后 R4/R5 必须已就绪,
数学上不存在 2 轮方案。R3 表中还钉了一条 `10.1.0.0/24` 明细,用于演示目标网段的
等价区间划分。`examples/diagnose.json` 是故障定位示例(1 条实测 + 5 条候选)。

## 原理

### 故障定位

- **场景** = 无故障 + 每条链路单独失效 + 每个出口单独失效。单一故障同时影响链路
  两端的下一跳解析(出口只影响挂载它的那台路由器)。
- **受影响路由** = 下一跳按现有解析(链路子网 / 出口子网,最长前缀优先)落在被中断
  链路或出口上的表项。撤下这些表项后,**其余表项重新按最长前缀逐跳转发**,因此可能
  回退到更粗的路由、走到别的出口,或形成环路——都要按仿真结果如实报出。
- **实测筛选**:逐场景逐条仿真实测记录,结果全部一致才保留。
- **归组**:对每条候选补测项仿真每个保留场景,结果向量完全相同的场景归为一组。
- **最少补测**:在所有候选组合中按规模从小到大搜索,找能区分任意两组的最小集合;
  同规模取字典序最小。各组在该集合上的结果即“预期补测结果”。
- **无法区分**:若某组含多个场景(它们在全部候选上结果相同),网页会明确标出
  “无法再细分”,需换入口或目标地址;若一条候选都没填,则提示先填补测项。
- **无场景符合**:所有场景都在某条实测上对不上时,提示“观测与假设不符”。

### 换表轮次规划

- **状态** = 已切换路由器集合(每台整表切换,共 2^N 个状态,N≤8)。
- **状态安全** ⇔ 每条保通要求、目标网段每个等价区间内,从入口按最长前缀匹配
  逐跳仿真,均落在允许出口(无断路/环路/错出口)。
- **等价区间**:把目标 CIDR 用所有表项中与之重叠的前缀切分,同一区间内所有地址的
  匹配结果在每台路由器的每张表中都相同,每类取一个代表地址验证,即覆盖“网段内任一地址”。
- **一轮合法** ⇔ 该轮起点到终点之间的所有中间状态(子立方体)都安全,因此同轮
  任意完成顺序都安全。在状态图上 BFS,求得**最少轮次**。
- **失败证据**:当前状态不安全 → 直接报“当前不通”;全部状态枚举后换不完 →
  在可达安全集边界上挑一个必然经过的失败状态,输出其逐跳路径与结论。

## 范围与限制

- 仅 IPv4 静态路由;链路按点到点处理;不支持递归下一跳、策略路由、动态协议。
- 路由器 ≤8 台(状态枚举 256 个,秒级完成);每张表 ≤500 条。
- 出口以“外部下一跳子网”建模,不校验对端接口 IP 是否真实配置。
- 故障定位只推演**单一**链路或单一出口失效;实测记录上限 200 条,候选补测项
  上限 12 条,仿真规模上限 20000 次探测。
